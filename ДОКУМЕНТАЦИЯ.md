## 4. РЕЗЮМЕ

### 4.1. Цели (предназначение, кратък анализ на потребностите и на съществуващите решения)

#### Предназначение

**RoadSense** е интегрирана система, съединяваща роботика, компютърно зрение, IoT (Интернет на нещата) и уеб технологии, с цел автоматизирана оценка на качеството на пътната настилка. Системата е предназначена за две основни групи потребители:

1. **Държавни органи и общини** — Проектът служи като евтин и ефективен инструмент за периодична инспекция на пътища, позволявайки на властите да идентифицират приоритетни зони за ремонт и да оптимизират разпределението на бюджета за пътна инфраструктура.
2. **Граждани и превозвачи** — Потребителите могат да преглеждат данни за актуалното качество на конкретни пътни отсечки в реално време чрез публично достъпна уеб карта. Това им позволява да вземат информирани решения при избор на маршрут и да избегнат участъци с лошо пътно покритие.

#### Анализ на потребностите

В България, както и в много развиващи се страни, значителна част от пътната мрежа е в незадоволително техническо състояние. Ямите и деформациите на пътното покритие са честа причина за:
- Пътнотранспортни произшествия и наранявания
- Повреди на превозни средства
- Увеличени разходи за гориво поради неравна настилка
- Неефективно управление на публичните средства поради липса на данни

Традиционните методи за инспекция на пътищата включват физически обход от специализирани екипи, което е бавно, скъпо и трудно мащабируемо. Съществуващите технологични решения (напр. специализирани превозни средства с лазерни скенери) са изключително скъпи и недостъпни за средните общини.

#### Анализ на съществуващите решения

| Решение | Предимства | Недостатъци |
|---|---|---|
| Ръчна инспекция | Точна, гъвкава | Бавна, скъпа, субективна |
| Специализирани измервателни автомобили | Много точни | Изключително скъпи (>100 000 €) |
| Мобилни приложения (crowd-sourcing) | Евтини, мащабируеми | Неточни, зависят от активността на потребителите |
| **RoadSense (нашият проект)** | **Автоматизиран, достъпен, обективен, в реално време** | **Покрива ограничена площ на сесия** |

Нашето решение запълва ниша между скъпите специализирани системи и неточните crowd-sourcing приложения, предлагайки обективни, автоматично събрани данни на достъпна цена.

### 4.3. Ниво на сложност на проекта − основни проблеми при реализация на поставените цели

Проектът обхваща множество технологични домейни, което го поставя на **високо ниво на сложност**. По-долу са описани основните технически предизвикателства, с които се сблъскахме:

#### Предизвикателство 1: Многозадачност в реално време на ESP32
ESP32 трябваше едновременно да изпълнява три задачи: следване на линия (изисква бързо реагиране — ~10ms цикъл), четене и изчисляване на сензорни данни, и изпращане на данни по WebSocket. Решихме проблема чрез **FreeRTOS задачи** — WebSocket комуникацията е делегирана на отделен CPU ядро чрез `xTaskCreatePinnedToCore()`, докато главният loop() се грижи за следването на линия и обработката на сензори.

#### Предизвикателство 2: Алгоритъм за оценка на качеството на пътя
Разработването на надежден алгоритъм, който комбинира данни от множество сензори (акселерометър, вибрационен сензор, температура, влажност) в единен индекс за качество от 0 до 1, изискваше значително изследване и тестване. Финалният алгоритъм е:

```
roughness = 0.8 * std_az + 0.4 * vib_normalized

traction_penalty:
  - temp < 5°C  → -0.4 (лед)
  - temp > 30°C → -0.3 (горещо, разлята настилка)
  - hum > 60%   → -0.3 (мокра настилка)

road_quality = (1 - roughness_normalized) * traction_factor
```

Основният показател е **стандартното отклонение на вертикалното ускорение (az)**, тъй като неравната настилка предизвиква значителни вариации в ускорението по вертикалната ос.

#### Предизвикателство 3: Синхронизация на данни от различни устройства
Данните от робота (ESP32) и от камерата (Raspberry Pi) трябваше да се обединят в един поток данни в сървъра. Реализирахме единна WebSocket точка за свързване, като всяко устройство изпраща своите данни (ESP32 — `roadQuality`, `condition`; Raspberry Pi — `holesCount`), а сървърът поддържа актуален агрегиран обект `latestSensorData`.

#### Предизвикателство 4: Детекция на ями с компютърно зрение в реално време
Разработка и тренировка на YOLOv8 модел за разпознаване на ями в условия на движение (вибрации, различно осветление) изисква правилно подбрана тренировъчна база данни и оптимизация за Raspberry Pi хардуер (намален размер на изображението до 320px за постигане на реално бързодействие).

#### Предизвикателство 5: Маршрутизация и визуализация на карта
Интеграцията на OSRM (Open Source Routing Machine) за изчертаване на реални пътни маршрути в Leaflet карта, с fallback към множество сървъри при недостъпност, изискваше имплементация на прокси endpoint в бекенда за избягване на CORS ограничения.

#### Описание на модулите

##### Модул 1: Роботизирана платформа (ESP32 — `Arduino/robot.ino`)
**Функция:** Автономно движение по маркирана линия и събиране на сензорни данни за качеството на пътя.

**Компоненти:**
- **Двигателна система (L9110S + 2 DC мотора):** Управление на движението напред/назад/завой. Скоростта се задава чрез PWM сигнали.
- **IR сензори за следване на линия (3 броя — ляв, среден, десен):** Четат контраста между бялата линия и тъмния фон. Логиката:
  - `M=0, L=1, R=1` → правo (пълна скорост)
  - `L=0, M=1, R=1` → рязък завой наляво
  - `R=0, M=1, L=1` → рязък завой надясно
- **MPU6050 (акселерометър + жироскоп):** Измерва ускорението по вертикалната ос (az). Стандартното отклонение на 10 последователни измервания е ключов показател за грапавостта на пътя.
- **DHT11 (температура и влажност):** Измерва метеорологичните условия, които влияят на сцеплението на настилката.
- **Вибрационен сензор (прекъсване):** Брои вибрационните импулси за секунда като допълнителна мярка за неравностите.
- **WiFi и WebSocket (ESP32 вgraден):** Изпраща агрегирани данни (`roadQuality`, `condition`) към сървъра на всяка секунда.

##### Модул 2: Визуален модул — Детекция на ями (Raspberry Pi — `Pothole/pothholeDetectRaspberry.py`)
**Функция:** Реално-временна детекция и броене на ями по пътя чрез компютърно зрение.

**Технология:** YOLOv8 (You Only Look Once v8) — модерна едноетапна невронна мрежа за детекция на обекти. Моделът е предварително тренован/дообучен върху набор от данни с изображения на ями (`Pothole/weights/best.pt`).

**Процес:**
1. Камерата (Picamera2) заснема кадри с резолюция 640×480
2. YOLOv8 анализира всеки кадър с намален размер (imgsz=320) за бързодействие
3. Брои откритите обекти от клас „яма" (`num_holes = len(results[0].boxes)`)
4. Изпраща `{"holesCount": N}` към сървъра по WebSocket на всеки 0.5 сек

##### Модул 3: Визуален модул — Детекция на пътни ленти (Raspberry Pi — `RoadDetection/`)
**Функция:** Разпознаване на пътните ленти за допълнителен анализ на пътното покритие.

**Технология:** Класически алгоритъм за компютърно зрение с OpenCV:
1. **Конвертиране в HLS цветово пространство** — по-добро разграничаване на белите/жълтите линии
2. **Sobel edge detection** (`edge_detection.py`) — намиране на ръбове с голям градиент на яркостта
3. **Перспективна трансформация (Bird's eye view)** — изглед отгоре за по-точна детекция
4. **Sliding Window алгоритъм** — намиране на пиксели от лентата с плъзгащ се прозорец
5. **Полиномиална апроксимация (2-ри ред)** — изчертаване на плавна крива
6. **Изчисляване на кривина и отклонение от центъра** — метрики за качество на пътния маркировка

##### Модул 4: Бекенд сървър (`backend/server.js`)
**Функция:** Централен хъб за обмен на данни между IoT устройствата и клиентите.

**Технологии:** Node.js, Express 5, WebSocket (ws библиотека), Supabase JS SDK

**Endpoints и функции:**
- `WebSocket /` — Двупосочна комуникация с роботи и браузъри:
  - Получава сензорни данни от ESP32/Raspberry Pi
  - Получава команди `start`/`stop` от работническото табло
  - Разпраща (`broadcast`) актуалните данни до всички свързани браузъри
- `POST /data` — HTTP алтернатива за ESP32 (ако WebSocket не е наличен)
- `POST /route` — Прокси към OSRM за изчисляване на маршрути (избягва CORS ограничения, опитва 3 OSRM сървъра с fallback)
- `GET /data` — Текущото форматирано съдържание на `latestSensorData`

**Логика за сесии и буфериране:**
При команда `start` + `roadId`:
- Инициализира се `measurementBuffer = []`
- Всяко получено измерване се добавя в буфера

При команда `stop`:
- Изчисляват се агрегирани стойности от буфера:
  - Средно качество (`avgQuality`)
  - Обща сума на ямите (`totalHoles`)
  - Най-честото условие (`avgCondition` — режим)
  - Средна GPS позиция
- Резултатът се записва като едно `measurement` в Supabase

##### Модул 5: База данни (Supabase/PostgreSQL — `db_schema.sql`)
**Функция:** Съхранение на данни за пътища и измервания с поддръжка на реално-временни актуализации.

**Таблици:**
- **`roads`** — Регистрирани пътни отсечки:
  - `id` (UUID), `name`, `status` (idle/recording), `description`
  - `start_lat`, `start_lng`, `end_lat`, `end_lng` — GPS координати
  - `waypoints` (JSONB) — межинни точки за сложни маршрути
- **`measurements`** — Сензорни измервания:
  - `road_id` (FK → roads), `quality` (float 0–1), `condition` (GOOD/MEDIUM/BAD)
  - `holes_count` (int), `latitude`, `longitude`, `timestamp`
- **`workers`** — Потребителски акаунти (свързани с Supabase Auth):
  - `id` (UUID), `full_name`, `email`

**Supabase Realtime** — Активирано за `roads` и `measurements` таблиците, позволявайки на браузъра да получава push актуализации при промяна на данните.

##### Модул 6: Фронтенд уеб приложение (`frontend/src/`)
**Функция:** Визуализация на данните за публични потребители и управление за работници.

**Технологии:** React 19, TypeScript, Vite, Tailwind CSS, Leaflet + react-leaflet, Supabase JS SDK

**Компоненти:**
- **`App.tsx`** — Routing с React Router Dom (2 маршрута: `/` и `/worker`)
- **`PublicView.tsx` (Публичен изглед):**
  - Свързва се с WebSocket за получаване на живи сензорни данни
  - Показва `roadQuality`, `holesCount`, `condition` в реално време
  - Интерактивна Leaflet карта с маркирани пътни отсечки
  - При клик на отсечка — показване на агрегирани исторически данни от Supabase
- **`WorkerDashboard.tsx` (Работническо табло):**
  - Автентикация с Supabase Auth (email/парола)
  - Добавяне на нови пътни отсечки чрез кликане на точки в картата
  - Стартиране/спиране на запис на измервания за избрана отсечка
  - Живи данни от робота в реално време
- **`Map.tsx`** — Споделен картен компонент с Leaflet:
  - Рисува пътните отсечки чрез OSRM маршрутизация
  - Оцветява маршрутите според качеството (зелено/жълто/червено)

#### Алгоритъм за оценка на качеството на пътя

Финалният алгоритъм е базиран на следния физически принцип: **неравната настилка предизвиква хаотични вибрации**, измерими чрез стандартното отклонение (σ) на ускорението по вертикалната ос (az).

**Стъпки:**
1. Събиране на 10 последователни измервания от MPU6050 в кръгов буфер
2. Изчисляване на σ(az) с формулата: `σ = √(Σ(xi-μ)²/n)`
3. Нормализация: `roughness = 0.8 * σ(az) + 0.4 * (vibCount / 10.0)`
4. Корекция за метеорологични условия (traction penalty)
5. Финален индекс: `roadQuality = (1 - clamp(roughness/1.5, 0, 1)) * traction`
6. Категоризация: `GOOD (>0.85) | MEDIUM (>0.45) | BAD (≤0.45)`

#### Алгоритъм за детекция на ями (YOLOv8)

**YOLOv8** (Ultralytics, 2023) е конволюционна невронна мрежа, която приема изображение и в единствен преход предсказва bounding boxes и класове за всички обекти. Архитектурата включва:
- **CSPDarknet backbone** — извличане на характеристики
- **PANet neck** — обединяване на характеристики от различни мащаби
- **Detection head** — предсказване на координати и класове

Моделът (`best.pt`) е тренирано/дообучено върху специфичен набор от данни за ями.

#### Алгоритъм за детекция на пътни ленти

Базиран на класически Computer Vision подход:
1. **HLS трансформация** — по-стабилна от RGB при различно осветление
2. **Sobel оператор** — изчислява градиент на интензитета: `mag = √(Gx² + Gy²)`
3. **Перспективна трансформация** — `getPerspectiveTransform()` + `warpPerspective()`
4. **Sliding Window** — итеративно търсене на бели пиксели в прозорец с адаптивен център
5. **Полиномиална апроксимация** — `np.polyfit(y, x, 2)` — крива 2-ри ред `x = ay² + by + c`

### Приложение Е: Исходен код на хардуерните модули

#### Е.1. ESP32 — firmware (Arduino C++)

Роботът използва три IR сензора за следване на линия, MPU6050 за вертикално ускорение, DHT11 за температура/влажност, вибрационен сензор за броене на импулси. Качеството се изчислява от стандартното отклонение на az и вибрациите; данните се изпращат по WebSocket (FreeRTOS задача на ядро 0).

```cpp
#include <Wire.h>
#include <Adafruit_MPU6050.h>
#include <Adafruit_Sensor.h>
#include <DHT.h>
#include <WiFi.h>
#include <WebSocketsClient.h>

const char* ssid = "YourWiFi";
const char* password = "YourPassword";
const char* serverAddress = "roadquality.onrender.com";
const int serverPort = 443;
WebSocketsClient webSocket;
float roadQuality;
String roadState;

#define IN1 26
#define IN2 27
#define IN3 25
#define IN4 33
#define LEFT_SENSOR   32
#define MIDDLE_SENSOR 35
#define RIGHT_SENSOR  34
#define DHTPIN 5
#define DHTTYPE DHT11
#define VIB_PIN 18

Adafruit_MPU6050 mpu;
DHT dht(DHTPIN, DHTTYPE);

int maxSpeed = 255;
int turnSpeed = 150;
int currentLeftSpeed = 0, currentRightSpeed = 0;

void motorLeft(int speed) {
  speed = constrain(speed, -255, 255);
  if (speed > 0) { analogWrite(IN1, speed); analogWrite(IN2, 0); }
  else if (speed < 0) { analogWrite(IN2, -speed); analogWrite(IN1, 0); }
  else { analogWrite(IN1, 0); analogWrite(IN2, 0); }
}
void motorRight(int speed) {
  speed = constrain(speed, -255, 255);
  if (speed > 0) { analogWrite(IN3, speed); analogWrite(IN4, 0); }
  else if (speed < 0) { analogWrite(IN4, -speed); analogWrite(IN3, 0); }
  else { analogWrite(IN3, 0); analogWrite(IN4, 0); }
}
void setMotorSpeed(int targetLeft, int targetRight) {
  motorLeft(targetLeft);
  motorRight(targetRight);
}

void lineFollow3Sensor() {
  int L = digitalRead(LEFT_SENSOR);
  int M = digitalRead(MIDDLE_SENSOR);
  int R = digitalRead(RIGHT_SENSOR);
  if (M == 0 && L == 1 && R == 1) setMotorSpeed(maxSpeed, maxSpeed);
  else if (L == 0 && M == 0 && R == 1) setMotorSpeed(maxSpeed - 40, maxSpeed);
  else if (R == 0 && M == 0 && L == 1) setMotorSpeed(maxSpeed, maxSpeed - 40);
  else if (L == 0 && M == 1 && R == 1) setMotorSpeed(-turnSpeed, maxSpeed);
  else if (R == 0 && M == 1 && L == 1) setMotorSpeed(maxSpeed, -turnSpeed);
  else if (L == 0 && M == 0 && R == 0) setMotorSpeed(maxSpeed, maxSpeed);
  else setMotorSpeed(0, 0);
}

volatile int vibCount = 0;
const int SAMPLE_COUNT = 10;
float azValues[SAMPLE_COUNT];
int indexA = 0;
unsigned long lastRoadCheck = 0;
const unsigned long ROAD_INTERVAL = 1000;

void IRAM_ATTR vibISR() { vibCount++; }

float computeStdDev(float *arr, int n) {
  float sum = 0, mean, stddev = 0;
  for (int i = 0; i < n; i++) sum += arr[i];
  mean = sum / n;
  for (int i = 0; i < n; i++) stddev += pow(arr[i] - mean, 2);
  return sqrt(stddev / n);
}

void webSocketEvent(WStype_t type, uint8_t * payload, size_t length) {
  if (type == WStype_CONNECTED) Serial.println("Connected to WebSocket");
  else if (type == WStype_DISCONNECTED) Serial.println("Disconnected");
}

void websocket_data(void* params) {
  while (1) {
    webSocket.loop();
    if (millis() - lastRoadCheck >= ROAD_INTERVAL) {
      String message = "{\"roadQuality\":" + String(roadQuality, 2) +
                       ",\"condition\":\"" + roadState + "\"}";
      webSocket.sendTXT(message);
      vibCount = 0;
      lastRoadCheck = millis();
    }
    vTaskDelay(pdMS_TO_TICKS(10));
  }
}

void setup() {
  Serial.begin(115200);
  pinMode(IN1, OUTPUT); pinMode(IN2, OUTPUT);
  pinMode(IN3, OUTPUT); pinMode(IN4, OUTPUT);
  pinMode(LEFT_SENSOR, INPUT);
  pinMode(MIDDLE_SENSOR, INPUT);
  pinMode(RIGHT_SENSOR, INPUT);
  pinMode(VIB_PIN, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(VIB_PIN), vibISR, RISING);
  Wire.begin();
  dht.begin();
  if (!mpu.begin()) { Serial.println("MPU6050 not found!"); while (1); }
  mpu.setAccelerometerRange(MPU6050_RANGE_4_G);
  mpu.setFilterBandwidth(MPU6050_BAND_10_HZ);

  WiFi.begin(ssid, password);
  while (WiFi.status() != WL_CONNECTED) { delay(1000); Serial.print("."); }
  Serial.println("\nWiFi connected");
  webSocket.beginSSL(serverAddress, serverPort, "/data");
  webSocket.onEvent(webSocketEvent);
  xTaskCreatePinnedToCore(websocket_data, "Task1", 4096, NULL, 1, NULL, 0);
}

void loop() {
  lineFollow3Sensor();
  sensors_event_t a, g, tempEvent;
  mpu.getEvent(&a, &g, &tempEvent);
  azValues[indexA] = a.acceleration.z;
  indexA = (indexA + 1) % SAMPLE_COUNT;
  float stdAz = computeStdDev(azValues, SAMPLE_COUNT);

  if (millis() - lastRoadCheck >= ROAD_INTERVAL) {
    float temp = dht.readTemperature();
    float hum = dht.readHumidity();
    float vibNorm = min(vibCount / 10.0, 1.0);
    float roughness = 0.8 * stdAz + 0.4 * vibNorm;
    float traction = 1.0;
    if (temp < 5) traction -= 0.4;
    else if (temp > 30) traction -= 0.3;
    if (hum > 60) traction -= 0.3;
    traction = max(traction, 0.4f);
    float normR = constrain(roughness / 1.5, 0.0, 1.0);
    roadQuality = (1.0 - normR) * traction;
    roadState = (roadQuality > 0.85) ? "GOOD" : (roadQuality > 0.45) ? "MEDIUM" : "BAD";
  }
}
```

#### Е.2. Raspberry Pi — детекция на ями (Python, Picamera2 + YOLOv8)

Скриптът заснема с Picamera2, обработва с YOLOv8 (imgsz=320), брои ямите и изпраща `holesCount` по WebSocket на всеки 0,5 s.

```python
from picamera2 import Picamera2
import cv2
import time
import json
import websocket
from ultralytics import YOLO

MODEL_PATH = "/home/boris/Documents/PothHole/Pothhole_Detect/best.pt"
WS_URL = "wss://roadquality.onrender.com"
SEND_INTERVAL = 0.5

model = YOLO(MODEL_PATH)
picam2 = Picamera2()
config = picam2.create_preview_configuration(main={"size": (640, 480)})
picam2.configure(config)
picam2.start()

ws = websocket.WebSocket()
try:
    ws.connect(WS_URL)
    print("Connected to WebSocket server at", WS_URL)
except Exception as e:
    print("Could not connect:", e)
    picam2.stop()
    exit()

last_send_time = 0
while True:
    frame = picam2.capture_array()
    frame_rgb = cv2.cvtColor(frame, cv2.COLOR_BGRA2BGR)
    results = model(frame_rgb, imgsz=320, verbose=False)
    num_holes = len(results[0].boxes) if results[0].boxes is not None else 0
    annotated = results[0].plot()
    cv2.putText(annotated, f"Holes: {num_holes}", (20, 40),
                cv2.FONT_HERSHEY_SIMPLEX, 1.1, (0, 255, 0), 3)
    cv2.imshow("YOLOv8 Detection", annotated)

    current_time = time.time()
    if current_time - last_send_time > SEND_INTERVAL:
        try:
            payload = {"type": "sensor_data", "holesCount": num_holes}
            ws.send(json.dumps(payload))
            print("Sent:", num_holes, "holes")
        except Exception as e:
            print("Failed to send:", e)
        last_send_time = current_time
    if cv2.waitKey(1) & 0xFF == ord('q'):
        break

picam2.stop()
cv2.destroyAllWindows()
ws.close()
print("Program terminated")
```
